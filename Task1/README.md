# Task 1 — ESP32-C6 Native IoT Development

## Overview

This project implements **Task 1 – Option A: Native IoT Development using ESP-IDF on ESP32-C6**.

The firmware provides:

- BLE-based Wi-Fi provisioning
- Dynamic Wi-Fi credential storage in NVS
- Wi-Fi station connection using provisioned credentials
- Automatic Wi-Fi reconnection after link loss
- SNTP-based system time synchronization
- MQTT connectivity using a public broker
- A FreeRTOS telemetry task that publishes a heartbeat every 5 seconds
- Heartbeat metadata containing device status, uptime, Wi-Fi state, and MQTT state

Wi-Fi SSID and password are **not hardcoded in the firmware**.

---

## Development Environment

- **Target:** ESP32-C6
- **Framework:** ESP-IDF
- **ESP-IDF version:** 6.1 or newer
- **Language:** C / C++
- **RTOS:** FreeRTOS
- **Provisioning transport:** BLE
- **MQTT broker:** `mqtt://test.mosquitto.org:1883`
- **MQTT topic:** `esp32c6/task1/heartbeat`
- **SNTP server:** `pool.ntp.org`

### File Responsibilities

#### `main/main.c`

Contains the main application flow:

1. Initialize NVS.
2. Initialize the Wi-Fi/provisioning manager.
3. Wait until the device receives an IP address.
4. Synchronize system time using SNTP.
5. Start the MQTT client.
6. Start the FreeRTOS heartbeat task.

#### `main/wifi_manager.cpp`

Handles:

- ESP-NETIF and Wi-Fi initialization
- BLE provisioning
- Checking whether Wi-Fi credentials already exist
- Wi-Fi connection state
- IP address events
- Automatic reconnect after disconnection

#### `main/wifi_manager.h`

Exposes the Wi-Fi manager interface used by the rest of the application.

#### `main/telemetry.cpp`

Implements the FreeRTOS telemetry task.

The task runs every 5 seconds using `vTaskDelayUntil()` and publishes a JSON heartbeat through MQTT.

#### `main/telemetry.h`

Exposes the telemetry interface used by `main.c`.

#### `main/idf_component.yml`

Declares the external ESP-IDF components used by the project:

- `espressif/network_provisioning`
- `espressif/mqtt`

## Wi-Fi Provisioning

On the first boot, if no Wi-Fi credentials are stored, BLE provisioning is started.

The BLE service name is generated from the ESP32-C6 MAC address in the following format:

```text
PROV_XXXXXX
```

The provisioning Proof of Possession used by this project is:

```text
abcd1234
```

This value is used only for the provisioning session. It is **not** the Wi-Fi password.

The Wi-Fi SSID and password are supplied at runtime using the BLE provisioning process and are stored in non-volatile storage by the ESP-IDF provisioning system.

On later boots, the stored credentials are reused automatically.

---

## Wi-Fi Reconnection

The firmware listens for Wi-Fi events.

When `WIFI_EVENT_STA_DISCONNECTED` occurs:

1. The internal connected state is cleared.
2. The Wi-Fi connected event bit is cleared.
3. `esp_wifi_connect()` is called again automatically.

This allows the ESP32-C6 to recover from a temporary Wi-Fi link loss without requiring a reboot.

---

## SNTP Time Synchronization

After the device receives an IP address, the firmware starts SNTP using:

```text
pool.ntp.org
```

The application waits up to 15 seconds for the initial synchronization.

When synchronization succeeds, the UTC date and time are printed in the ESP-IDF log.

---

## MQTT

The MQTT client connects to:

```text
mqtt://test.mosquitto.org:1883
```

Heartbeat messages are published to:

```text
esp32c6/task1/heartbeat
```

The firmware tracks MQTT connection and disconnection events.

Telemetry is published only when both Wi-Fi and MQTT are available.

---

## Heartbeat Message

The FreeRTOS heartbeat task runs every 5 seconds.

Example payload:

```json
{
  "device": "esp32c6",
  "status": "online",
  "uptime": 120,
  "wifi": true,
  "mqtt": true
}
```

### Payload Fields

| Field | Description |
|---|---|
| `device` | Device platform |
| `status` | Current device/network status |
| `uptime` | System uptime in seconds |
| `wifi` | Wi-Fi connection state |
| `mqtt` | MQTT connection state |

When Wi-Fi or MQTT is unavailable, the telemetry task skips publishing until connectivity is restored.

# Build Instructions

## 1. Install ESP-IDF

Install ESP-IDF and configure the VS Code ESP-IDF extension.

This project was prepared for ESP-IDF 6.1.

Verify the installation:

```powershell
idf.py --version
```

Expected output should show ESP-IDF 6.1 or a compatible newer version.

---

## 2. Open the Task1 Project

Open the `Task1` directory as the ESP-IDF project folder.

Example:

```powershell
cd D:\assingment\Task1
```

All `idf.py` commands must be executed from the directory containing the top-level `CMakeLists.txt`.

---

## 3. Set the ESP32-C6 Target

```powershell
idf.py set-target esp32c6
```

If `IDF_TARGET` is already set to another chip in the current terminal, clear it first:

```powershell
Remove-Item Env:IDF_TARGET -ErrorAction SilentlyContinue
idf.py set-target esp32c6
```

---

## 4. Resolve Components

```powershell
idf.py reconfigure
```

ESP-IDF Component Manager reads `main/idf_component.yml` and resolves the required MQTT and network provisioning components.

---

## 5. Build

```powershell
idf.py build
```

A successful build generates the application image inside:

```text
Task1/build/
```

# Flash Instructions

Physical ESP32-C6 hardware is required for flashing and runtime validation.

## 1. Connect the ESP32-C6

Connect the board over USB and identify its serial port.

In VS Code, the port can be selected using:

```text
ESP-IDF: Select Port to Use
```

Example port:

```text
COM5
```

---

## 2. Flash the Firmware

Replace `COM5` with the actual serial port:

```powershell
idf.py -p COM5 flash
```

---

## 3. Open the Serial Monitor

```powershell
idf.py -p COM5 monitor
```

Build, flash, and monitor can also be executed together:

```powershell
idf.py -p COM5 flash monitor
```

Exit the ESP-IDF monitor using:

```text
Ctrl + ]
```

---

# Expected First-Boot Behaviour

For a device with no saved Wi-Fi configuration, the logs should show the provisioning process starting.

Typical sequence:

```text
NVS initialized
BLE provisioning started
Device is not provisioned
BLE provisioning device: PROV_XXXXXX
Provisioning PoP: abcd1234
```

After Wi-Fi credentials are supplied:

```text
Received Wi-Fi credentials for SSID: <SSID>
Provisioning successful
Wi-Fi connected. IP: <IP ADDRESS>
Starting SNTP
SNTP synchronized: <UTC TIME>
MQTT client started
MQTT connected
Heartbeat task started
```

Heartbeat messages are then generated every 5 seconds.

---

# Reboot Behaviour

After successful provisioning, the Wi-Fi credentials remain stored in NVS.

On the next boot, the firmware should detect the stored configuration and connect without starting a new provisioning session.

Typical log:

```text
Wi-Fi credentials already stored in NVS
Wi-Fi station started
Wi-Fi connected. IP: <IP ADDRESS>
```

---

# Re-Provisioning / Erasing Flash

To remove stored Wi-Fi credentials and return the device to a first-boot state:

```powershell
idf.py -p COM5 erase-flash
```

Then flash the firmware again:

```powershell
idf.py -p COM5 flash monitor
```
